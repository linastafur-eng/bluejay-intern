# Compare recruiting discovery queries

For Bluejay internships, follow [internship agent instructions](../../AGENTS.md) and [sender setup](../../email-handoff.md). Authorized discovery toward 100 leads continues with or without a sender handoff. Sender examples and feedback on five drafts update their private writing guidance; Codex sends an explicitly instructed, approved template/recipient batch through the connected sender mailbox. This sourcing skill itself does not dispatch mail. Other roles keep their own policy.


Use within [source recruiting prospects](../source-recruiting-prospects/SKILL.md). Follow project review gates before expanding toward 100 distinct leads; discovery is separate from assessment.

For Bluejay internships, save every countable person as a row in [the run's one native database](../../notion-runs.md), including discovery-only people. If 105 people are found, the All people view must contain 105 distinct rows. Do not split people across static tables or use deleted run history as the new baseline.

## Compare fairly

- Read the current role/version, attributed feedback and query history. Record provider, time, permitted channels, prior identities, run key, target and checkpoint budget.
- Test direct work, adjacent experience and challenger routes. For Bluejay include GitHub, public X and university/co-op routes. Any or no university affiliation is eligible.
- Predeclare comparable depth, normally ten results per query. Issue queries separately; retain ID, exact text, rank, URL, provider and time. Pooled unattributed results are exploratory only. Changed queries get new IDs.
- Inspect the declared depth before comparing or expanding. Record missing returned slots and classify each result: plausible person, nonperson, wrong role/level, stale, unresolved or duplicate.
- Count a lead only after reading an attributable primary profile with a concrete relevant claim and no identity conflict. Snippets and repository owners alone do not qualify. A course or student-facing project does not establish enrollment.
- Deduplicate using explicit identity links, retaining every origin. Name searches are verification, not discovery. Report total, new and reused people separately.

## Adapt the search

- Compare distinct plausible people per inspected result, profile resolution, duplicates, evidence coverage and calls/time. Report cross-query overlap and unique contributions without favoring the first query.
- Keep fixed-depth comparisons separate from deeper expansion. Use [the evaluation contract](../../decision-trees.md) for formulas and audit checks.
- Expand promising queries while reserving a declared exploration allowance, normally at least 25% of subsequent trials. This is adjustable research allocation, not a hiring weight or school quota.
- Record route failures. Weak X indexing does not establish weak candidates. Never optimize only for prestige, popularity or matching keywords.
- Save observed results, attributed feedback, failure explanations and next-run baseline/challenger queries. Missing feedback is unavailable, not rejection. MTS labels are not internship outcomes.
- Query adaptation is allowed; criteria, weights and skills require separate authorization. Test fresh people before claiming better hiring quality.

## Save a resumable run

- Respect the project stage. For an authorized full discovery run, continue toward 100 countable people without padding. Normally checkpoint after 40 trials or 200 profile checks; a checkpoint is not completion.
- Save actual counts, remaining work and blockers when incomplete. Resume useful work within authorized scope.
- Keep identities, query IDs/ranks, source-supported relevance, evidence status, dates, role/version and feasibility unknowns in private Notion. Contact details are unnecessary.
- Save intended writes and recovery data in ignored runtime/private-data. Serialize by role/run, reconcile uncertain writes and preserve human notes.
- Direct-read outputs and verify distinct countable records before completion. Update the latest discovery link only after readback; preserve the last completed assessment packet.
- Keep candidate data out of GitHub and Space. Do not contact, share, schedule or merge through this skill.
