# Review GitHub work

- Confirm the account through an explicit profile link or candidate-supplied identity evidence. A matching name is insufficient.
- Record repository, commit/ref, file paths and observation date. Distinguish original work, upstream contributions, forks, tutorials and generated files.
- Trace a relevant feature or fix through implementation, failure handling, edge cases and tests. Read review discussion and maintenance history when available.
- Attribute only supported individual contributions. A contributor does not own every repository change. AI assistance alone is not negative evidence.
- Map findings to the current role criteria. Use numeric anchors only when that role's rubric is explicitly active; internships use qualitative criteria.
- Separate static inspection from executed tests and historical artifacts from current practice. Do not execute candidate code in this workflow or claim tests passed from reading them.
- Stars, contribution grids and README polish do not establish skill or adoption. Cite concrete implementation and credible usage evidence.
- Missing public code or unresolved identity stays Unknown. Suggest a linked work sample or technical discussion; ask about a concrete tradeoff or failure.

Return inspected artifacts, evidence by criterion, attribution limits and the next verification question. Keep candidate data private.
