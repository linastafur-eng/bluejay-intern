# Source recruiting prospects

For Bluejay internships, follow [internship agent instructions](../../AGENTS.md) and [sender setup](../../email-handoff.md). Authorized discovery toward 100 leads continues with or without a sender handoff. Sender examples and feedback on five drafts update their private writing guidance; Codex sends an explicitly instructed, approved template/recipient batch through the connected sender mailbox. This sourcing skill itself does not dispatch mail. Other roles keep their own policy.


For Bluejay internships, [the native run database contract](../../notion-runs.md) is required: one database per run, one person per row, with discovery, assessments, decisions and drafts in the same rows. A 105-person run has 105 rows. Read only active-run feedback; fresh runs start empty and deleted results must not be restored.

## Establish scope

- Read the project AGENTS.md, current Notion role brief, sourcing guidance, query history and human feedback. Resolve consequential conflicts without overwriting human edits.
- Record role/version, outcomes, required versus teachable skills, permitted sources, constraints, evidence expectations, output counts and private Notion destination. Ask only about missing inputs that change qualification or access.
- For Bluejay internships use [the role reference](../../README.md#candidate-evaluation) and current Notion brief. Other roles need their own requirements.
- Keep search hypotheses separate from requirements. Do not infer protected traits, availability, willingness or salary. For Bluejay, apply Lina's role-reference hierarchy: verified selective technical recognition and similarly strong engineering internships, then strong attributable GitHub, then distinguished-university signals. University affiliation can Advance an initial screen without establishing technical strength. Record initial screen separately from observed-work band; missing public code does not erase verified recognition. Popularity alone is not ability.

## Discover and assess

- Use [discovery queries](../discover-recruiting-queries/SKILL.md). For internship review runs, deliver five assessed prospects, then ten after feedback, before explicitly authorized discovery expansion toward 100.
- Search direct work, adjacent experience and a challenger route. Include public GitHub/X and university/co-op routes when relevant; any or no university affiliation is eligible. Use network sources only within explicit authorization. No bulk LinkedIn scraping or private contact panes.
- Record exact queries, first discovery URLs, verification queries, observation dates and inclusion reasons. Name-specific checks verify identity; they are not independent discovery.
- Inspect current work, up to three prior employers where listed, grouped promotions and all listed education. Fewer employers does not penalize interns.
- Verify identity links and personal contribution before attributing artifacts. For engineering use [GitHub review](../review-github/SKILL.md); do not execute candidate code. Missing public work is Unknown, with a work sample or discussion as a next step.
- Apply the role's qualitative criteria. For Bluejay internships, treat technical depth, end-to-end product building and founder-like initiative similarly; verify attribution and correctness across them. Use the role reference's evaluation priorities and Standout / Strong / Decent / Mixed / Weak for this role / Needs verification bands, with confidence and a reason. Use qualitative bands and intern-level evidence. Numeric scoring for other roles requires an explicitly activated, evaluated role rubric. Keep evidence coverage, demonstrated ability, fit, feasibility, interest and human decisions separate.

## Deliver and verify

- Save role/version, search history, actual counts, assessments, evidence by criterion, unknowns and next questions in private Notion.
- Write two or three short reason bullets and one recommendation sentence explaining why review or hold, plus the main concern. Label profile claims and inspected findings. Put source/commit/file links, experience, education and detailed criteria beneath the summary.
- Rank only as provisional research priority, explaining meaningful differences. Never pad a target or invent precision. Include unsent drafts only when requested.
- Serialize by role and input digest. Save intended writes and page IDs in an ignored private manifest. Read the destination, deduplicate canonical identities and reconcile uncertain writes before retrying.
- Preserve human text, decisions, native children and prior assessments. Changed evidence or criteria gets a new assessment version. Identical verified input is a no-op.
- Direct-read every output before reporting delivery. Verify identities, sources, role/version, counts, order and draft bodies. Mark incomplete work honestly; retain the last completed-run link.
- Keep candidate/contact data out of GitHub and Space. Existing MTS maintenance stays separate. This skill does not authorize sending, mailbox drafts, invitations, sharing, schedules or merging.

For internships use [the process and decision trees](../../decision-trees.md). Other roles use [the decision map](../../decision-trees.md) and their own active policy.
