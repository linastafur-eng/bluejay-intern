# Set up another sender for Codex outreach

Codex sends through the named sender's connected mailbox. The sender supplies writing guidance and feedback; Lina reviews candidates. Handoff and discovery expansion proceed on separate branches.

## Calibrate the sender's writing

- Confirm the sender's name, signature and mailbox. They connect their own mailbox in the Codex session that will send.
- Collect a few writing examples, desired tone, phrases to use or avoid, length and preferred call to action in private Notion.
- Draft five emails using the shared Bluejay structure. These are calibration drafts, not sent emails.
- Ask the sender to edit or comment on all five. Read the actual feedback and identify which drafts it applies to.
- The writing skill updates that sender's private guidance automatically, records the feedback author and a new version, and revises the five drafts. Show the changes and resolve conflicting feedback.
- The sender confirms the shared template and voice. Lina approves the recipient batch. Routine matching emails need no individual copy approval.

Keep writing examples, feedback and sender-specific guidance private. Read the current guidance on every drafting run. Never copy one sender's voice into another sender's profile or rewrite company facts, sourcing criteria or sending permissions from writing feedback.

## Keep discovery moving

After the candidate review checkpoints and an instruction to expand, continue toward 100 distinct discovery leads whether outreach uses Lina's mailbox or another sender's. Missing writing feedback or mailbox access blocks sending, not authorized discovery. A hundred discovery leads is not an approved hundred-recipient email batch.

## Prepare the Notion queue

Each item records the candidate/role, sourced recipient, sender/mailbox, final subject/body, personalization source, sender-style version, shared-template version and recipient-batch approval. Record any send instruction's batch scope and approving actor.

Use Draft, Needs sender feedback, Needs setup approval, Ready for Codex, Sent, Delivery unknown or Do not contact. Retain the queue's status labels and record the current stage and shared approvals in the item body.

Grant the sender only authorized Notion access or an approved minimal projection. A filtered view is not an access boundary.

## Codex sends and records delivery

An explicit instruction to send may cover the selected batch; it does not need to be repeated for each matching email. A Ready status alone is not that instruction.

Before each send, Codex verifies the connected mailbox matches the named sender, recipient identity, approved batch and template, current opt-out/hold/pause state and duplicate/unknown delivery. Missing or conflicting inputs hold that item. New claims, changed sender or recipients outside the approved scope need review.

Codex uses the connected mail tool and records the returned message ID or sent-message link, sender and time in Notion. Mark Sent only after provider evidence. If delivery is unclear, reconcile before retrying.

Sending requires the correct connected mailbox and the batch instruction at execution time.
